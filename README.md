# 會提醒你的智慧狀態監控器（NUCLEO-G474RE 期中專題）
未按時確認巡檢就自動升級警報，從綠燈正常、黃燈閃爍一路到紅燈與蜂鳴器危急警報，支援外部中斷手動復歸。

## 1. 情境故事：誰、在哪、遇到什麼麻煩
* **誰**：工程師老王
* **在哪**：精密儀器實驗室
* **遇到什麼麻煩**：設備運作時需要定期到機台前按下確認鈕進行巡檢，但老王常因專注於其他文件而忘記時間，導致機器差點陷入危急狀態。智慧狀態監控器透過漸進式聲光警報與 EXTI 中斷強制復歸來解決人為疏忽。

## 2. 替身對照：故事裡的模組 → 板上替身
* 大型工業機台 / 實驗儀器 → NUCLEO-G474RE 開發板與麵包板電路
* 現場操作員 / 工程師老王 → PC13 外部按鈕 (`button`)
* 機台三色狀態燈號 → PC5 (`led_green`)、PC6 (`led_yellow`)、PC8 (`led_red`)
* 廠房警報器 / 蜂鳴器 → PC9 蜂鳴器 (`buzz`)
* 實際定期巡檢間隔 (數小時) → 毫秒級時間縮放 (5秒 $\rightarrow$ 10秒)

## 3. 功能與驗收條件：動作、預期、實測結果
* **動作 1（開機正常）**：上電後系統預設進入綠燈恆亮狀態。
  * **預期**：`led_green` 亮起，維持 5 秒。
  * **實測結果**：(填入實際測試狀況，例如：通過，開機 5 秒內綠燈恆亮)
* **動作 2（預警催促）**：超過 5 秒未按按鈕。
  * **預期**：自動切換為黃燈閃爍，持續 10 秒。
  * **實測結果**：(填入實際測試狀況，例如：通過，5秒後 `led_yellow` 以 250ms 間隔閃爍)
* **動作 3（危急警報）**：黃燈閃爍超過 10 秒仍未按按鈕。
  * **預期**：轉為紅燈與蜂鳴器同步急促閃爍及鳴叫。
  * **實測結果**：(填入實際測試狀況，例如：通過，10秒後 `led_red` 與 `buzz` 同步以 200ms 閃爍/鳴叫)
* **動作 4（手動復歸）**：在任意階段按下 PC13 按鈕。
  * **預期**：觸發 EXTI 外部中斷，瞬間強制歸零回到綠燈狀態。
  * **實測結果**：(填入實際測試狀況，例如：通過，按下按鈕後立即重置計時並回復綠燈)

## 5. 腳位表：用到的每支腳位與用途
* `PC5` = `led_green`（正常狀態綠燈）
* `PC6` = `led_yellow`（預警狀態黃燈）
* `PC8` = `led_red`（危急狀態紅燈）
* `PC9` = `buzz`（危急警報蜂鳴器）
* `PC13` = `button`（外部中斷按鈕 / B1 復歸按鈕，EXTI13）
* `PA2 / PA3` = `USART2` (ST-LINK VCP 虛擬 COM 埠，保留調試)

## 6. 建置與執行：開發環境、燒錄步驟、終端機設定、命令
* **開發環境**：STM32CubeIDE (支援 STM32G474RE)
* **燒錄步驟**：透過 ST-LINK USB 連接開發板，點擊 Run / Debug 直接燒錄至晶片。
* **執行流程**：
  1. 上電重置 $\rightarrow$ 綠燈亮 (5s)
  2. 未按按鈕 $\rightarrow$ 黃燈閃爍 (10s)
  3. 逾時未處理 $\rightarrow$ 紅燈 + 蜂鳴器危急警報
  4. 隨時按下 `PC13` 實體按鈕 $\rightarrow$ 觸發 EXTI 中斷強制復歸回綠燈。

## 7. 程式結構：哪個檔做什麼、ISR 與主迴圈分工
* `main.c`：
  * **主迴圈 (`while(1)`)**：運行非阻塞式狀態機 (`switch-case`)，依據 `HAL_GetTick()` 判斷時間差來切換燈號與閃爍頻率。
  * **中斷服務函數 (`HAL_GPIO_EXTI_Callback`)**：處理 `button_Pin` (`PC13`) 的外部中斷，負責即時攔截並強制將狀態重置為 `STATE_GREEN`。
* `main.h`：存放自動生成的 User Label 巨集 (`led_green_Pin`, `buzz_Pin`, `button_Pin` 等)。

## 9. AI 使用說明：哪段請 AI、你怎么查核
* **請 AI 協助的段落**：非阻塞式狀態機 (`HAL_GetTick()`) 的時間差運算邏輯、STM32CubeIDE 外部中斷回調函數 (`HAL_GPIO_EXTI_Callback`) 的編寫，以及投影片/README 排版結構。
* **你怎麼查核**：核對 STM32G4xx Reference Manual 確認 EXTI 中斷暫存器與 GPIO 設置無誤，並實際燒錄至開發板驗證 5 秒、10 秒倒數與按鈕強制中斷是否如預期運作。

## 10. 已知限制：哪些用替身、換真貨要改哪裡
* **已知限制**：目前以麵包板上的 LED 與小型蜂鳴器作為「替身」來模擬工業現場的聲光警報。
* **換真貨要改哪裡**：若未來要接入真實工廠的 24V 工業重載警報塔與電磁閥，只需將 `PC5/6/8/9` 的 GPIO 輸出改透過繼電器 (Relay) 或 MOSFET 驅動模組進行隔離控制即可。
